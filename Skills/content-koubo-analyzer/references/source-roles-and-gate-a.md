# 来源角色、融合与 Gate A

## 1. 逐篇拆解

对每篇参考分别回答：

1. 它对谁说，试图解决什么问题；
2. 核心承诺或立场是什么；
3. 开头怎样让目标受众继续听；
4. 正文怎样推进和兑现承诺；
5. 最值得迁移的内容价值、结构功能和表达机制；
6. 哪些身份、经历、案例、公司业务、数据、承诺或原句不得转移。

有正文证据时写明确观察；没有传播数据时，只能说机制可能怎样影响理解、信任或行动，不能把分析写成已证明的爆款因果。

## 2. 多篇融合

先逐篇拆，再融合。不要把多篇原文先拼成一篇。

- 合并相同问题、内容价值和机制；
- 说明每篇分别贡献什么；
- 去掉重复借点；
- 对互相冲突的观点、受众、承诺或结构建立 `conflicts[]`；
- 每个冲突至少绑定两个 `reference_id`，说明采用、一般化或舍弃的理由；
- 无真实冲突时使用空数组，不制造冲突凑字段；
- 不把多篇内容顺序直接拼成目标口播顺序。

## 2.1 一份分析，两种用途

- `reference_analyses + fused_direction` 组成同版详细拆解报告，保留逐篇内容价值、钩子、结构、可迁移项、禁止迁移项和真实冲突处理；
- `customer_readable_direction` 只是同一报告的客户确认投影，不是第二次分析；
- Gate A 只把客户投影分成五组展示：谁来说、讲给谁；核心观点和承诺；对标准备保留什么；哪些内容不照搬；准备怎么讲；
- Gate A 批准后，Writer 必须使用同版详细拆解报告形成的详细蓝图，不能只使用五组客户摘要；
- 两种用途必须绑定同一 `direction_version`。任何受众、核心承诺、迁移边界或结构冲突都必须在展示前停止，不能生成“客户确认一版、Writer 执行另一版”的双轨结果。

## 3. 04 双角色

### `peer_content_asset`

允许提供：

- 选题价值与问题主线；
- 通用观点和判断方法；
- 普通用户场景、内容顺序和细节方向；
- 同行内容中已经完成的一般化拆解。

不得提供当前客户的身份、经历、案例、业务、产品、业绩、承诺或未经核验的专属数据。

### `oral_method_asset`

允许提供：

- 钩子功能；
- 结构和推进方式；
- 注意力重置、例子、对比、增强机制；
- 收束或 CTA 方法。

它不提供客户事实，也不单独决定选题和立场。

候选不相关时不要选择。有外部参考且没有高相关 04 时，`selected_method_assets` 可以为空。零外部参考时必须实际采用可用 04，`reference_analyses`、`external_reference_value`、`borrowed_value` 为空，不造客户参考；详细蓝图由已选 04 的具体 `usage`、完整内容和 `fused_direction.structure_plan` 承载。

同行不只提供句式，还提供问题主线、观点、场景、判断依据和细节价值；结构提供组织方法，增强技巧只做局部增强。总方法论指导选材，不冒充独立内容素材。区分资料中的观点与客户明确观点、事实与假设、写作要求与要进入正文的内容。内部控制只能执行，不机械朗读。使用范围或正文有冲突时明确排除或核实，不凭 active 标签升级。

## 4. Writer 模式建议

先判断希望读者发生什么变化，再建议一个主模式：

- `explain` 常见于 `ganhuo`：让读者理解、学会或会判断；
- `discuss` 常见于 `huati`：引发共鸣、观点变化或讨论；
- `convert` 常见于 `zhuanhua`：推动了解、咨询或采取行动。

这不是固定映射。结合受众、承诺、对标结构、用户想法和预期行动说明理由。只选一个主模式；混合需求放入少量 `secondary_tactics`，不要创建混合 Writer 或同时加载三套规则。

## 5. 客户阅读方向

`customer_readable_direction` 必须完整、普通人一遍能看懂，并包含：

1. `original_topic`：逐字复制 `topic_original`；
2. `target_audience`：根据选题、参考和 04 候选作出明确判断，交由 Gate A 用户确认；
3. `core_promise`：与融合方向逐值一致；
4. `borrowed_value`：逐篇或融合说明外部参考借什么；
5. `method_asset_usage`：说明选中 04 的角色和参与方式；为空时明确无高相关 04，不补无关页面；
6. `oral_structure`：用普通语言说明准备怎样推进，不预写正文；
7. `user_boundaries`：原样带回用户想法、必须保留和不要写成；
8. `speaker_mode_explanation`：用普通语言解释当前讲述者模式；
9. `writer_recommendation`：一个主模式和与 `writer_mode_reason` 同值的业务理由；
10. `generalization_boundary`：与融合方向同值，说明同行专属内容不会转移，哪些内容会一般化、条件化或舍弃。

`borrowed_value` 必须与融合方向的 `external_reference_value` 同值，`oral_structure` 必须与 `structure_plan` 同值，`method_asset_usage` 必须逐项对应已选资产的 `usage`。不允许生成“展示一份、批准时冻结另一份”的双轨方向。

不要出现 Run、Artifact、Bundle、Schema、SHA、Packet、Reviewer 等内部词。

## 6. 普通修改

`revision_request` 存在时：

- 保持同一原始选题、参考集合、客户、讲述者模式、已展示受众和核心任务身份；
- 按非空用户意见重新生成完整输出；
- 不只返回差异或补丁；
- 不覆盖、否认或重签旧方向；
- 如果意见实质改变任务身份，停止并要求新 Run。
