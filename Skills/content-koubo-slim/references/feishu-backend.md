# 飞书后端

## 连接与预检

飞书沿用公共 content-source-v1，不需要本地同步知识库。宿主需有已认证的 lark-cli，运行时显式使用 user 身份。

已有 binding 首次连接口播：

```text
content_koubo_slim.py configure-feishu --binding-id <已登记 binding> --profile <本次明确选择的 IP>
```

读取零写入预览；用户已明确授权此连接时，以该次返回的 confirmation 传回同命令完成合并。只新增口播支持、输出和默认 Profile，保留公众号配置，分别回读 Manifest 与 Registry。配置变化导致 confirmation 失效时重新预览，不绕过校验。若远端配置已更新而本地写入失败，重新预览复用远端结果，完成余下合并。

```text
content_koubo_slim.py preflight --profile <本次 IP>
```

预检读取身份、配置和 Profile 校验，不创建 Run，不生成内容，不代表三次 Gate 的任何批准。start 接收 0—5 篇可读本地参考；无外部参考时沿用 1.2.0 库内选材分支。

## 资料边界

- Manifest、Profile 索引及逻辑根必须属于已选空间；逻辑根不能互相重叠。
- 03/04/05 的引用在各自授权根内回读；跨空间、快捷方式、循环和失效摘要阻断，不能当成无命中。
- 受控来源字段中的 `feishu:<token>` 表示远端对象，不是本地文件路径。运行时完成节点和文档对象解析，模型不得猜 token。
- P2 仅检索 04，P3 才按批准需求检索 03 并装配本次 Profile；候选数量与唯一 Context Pack 不变。
- 飞书先按目录标题筛选，最多读取 12 份候选正文再执行原有排序；不把所有文档全文装入上下文。原有类型与 audience_scope 合同仍适用；旧 `oral_template_deconstruction` / `internal_only` 资产不会被自动改写成新类型，也不会绕过适用范围进入候选。
- `discover-methods` 在飞书只返回有界目录标题和真实引用，不读取全部正文。Agent 先选少量标题，再对选中引用使用 `--read-path`；首次远端读取可不提供摘要，返回完整资料与 `page_sha256`。随后选材文件必须带该摘要，start 再次回读校验；本地发现仍要求已发现的摘要。同行、方法和指引预算与 1.2.0 相同。
- 飞书摘要基于客户端规范化后的 Markdown：换行统一 LF，首尾空白收束，末尾一个换行。Profile 索引与正文必须采用相同口径，失配时停止，不能自动重写摘要以掩盖漂移。
- 原生 Profile 没有 YAML 头时，以已校验索引中的身份、active 状态、指定对象和精确摘要共同定位；正文里的旧兼容 ID 不参与身份解析。有 YAML 头时仍检查其与索引一致。

## 两份最终文档

“确认并保存”后分别保存纯口播稿和发布配套，使用 Manifest 授权的 output 根及口播输出模板。两份均 create-only，不合并、不覆盖，不发布。

本地 Run 保存请求和回读回执，远端部分成功时保留同一个 Run。第二份失败不能报告 saved；重试复用已核实的第一份。创建结果未知时停止核实，不盲目重试创建，也不认领无回执的重名文档。真实已确认正文及配套不得为恢复操作重新生成。

多篇任务仍每篇独立 Run 和三次确认，远端标题带批次条目后缀；已保存正文修订生成带正文版本的两份新文档，保留旧文档。回执位于 `feishu-save/vN/`，冻结版本、条目、目标及内容。批量状态通过只读回读空间、祖先、对象、标题唯一性及正文摘要判断完成，不调用保存器补写。

飞书后端不自动迁移旧 Run 回执。恢复旧 Run 前须单独核实其回执与当前版本的兼容性。
