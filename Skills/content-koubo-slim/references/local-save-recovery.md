# 本地双文件保存恢复

所有最终目标保持 create-only。当前 Run 的 `local-save/local-save.json` 记录冻结请求、时间和已核验的两个目标、内容摘要及文件身份；不保存额外正文副本。

- write、flush、fsync 或回读失败：清理当前调用实际创建且文件身份仍匹配的文件；不删除已有文件或被替换的文件。操作系统拒绝清理时保留现场并失败，不能报告完成。
- 两份写入并回读成功后，原子持久化完整回执，再推进 Run 到 saved。推进前失败可在原 Run 重试；package_approved 和保存失败后 blocked 的入口均复用批准内容及标题。
- 完整回执存在时，只复用位置、文件身份与正文摘要均匹配的两份文件。跨日期重试仍使用回执冻结的日期。
- 只有请求回执、没有完成回执时，不认领任何既有同名文件，即使内容相同。进程在创建与持久化完成回执之间崩溃、回执损坏或临时回执残留时，应人工核实，不能盲目清理或重写。
- 不允许把无回执的旧 Run 输出自动转换成新回执。新增回执文件不改变三个真人停点。
- 目录、祖先和最终目标的软链接及 Windows reparse point 均不作为写入授权路径。

回执提供保守的故障恢复，不承诺任意断电、恶意并发路径替换或文件系统损坏下的全事务原子性。未完成双文件回读与回执核验时不得报告 saved。
# 版本化保存回执

保存回执按正文版本放在 `local-save/vN/`；批次条目后缀和正文版本共同进入请求与文件名。不同正文版本不得共用回执。批次重试也只接受持久化完成回执，不因文件内容相同而认领已有文件。历史旧目录回执不自动迁移或推断归属；恢复旧 Run 前须另行审查兼容性。
