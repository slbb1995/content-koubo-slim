# 合集中的逐篇参考

用户给的一个文档含多条独立口播、文章或案例时，先读本页。文件数量不等于篇目数量；程序不会用标题正则替 Agent 判断篇目。

## 准备

1. 用宿主已具备的文档读取/转换能力取得完整 MD/TXT。DOCX 改扩展名不等于转换；正文、表格或结尾未完整取得时，说明缺失并停止该参考的使用。
2. 按内容识别独立开场、推进、结尾与原有篇目分隔。文章的小标题、编号步骤不应拆成独立口播。边界实质不清时只询问缺失信息，不自行猜分。
3. 一个文件只有一篇时仍直接传原 MD/TXT；含多篇时创建内部 `*.reference-map.json`，按转换后的完整文本行号登记每篇，保留源文件 SHA256。不得先概括原文再将摘要作为参考。
4. 本次最多选5篇，按篇计数，不按文件计数。超过时让用户选择范围，不能悄悄只取前5篇；封面说明、目录等不属于正文的范围须记录排除原因。
5. 把映射文件作为既有 `start --reference` 参数传入。程序只读取、校验和冻结切片，不改原件；随后每个 REF 都必须有独立分析，再融合方向。向客户显示原文件与篇名，无需显示行号、哈希或内部映射文件。

## 内部映射

```json
{
  "source_path": "本机已核验MD或TXT的绝对路径",
  "source_sha256": "完整源文件原始字节的SHA256",
  "items": [
    {"title": "原文第一篇标题", "start_line": 2, "end_line": 9},
    {"title": "原文第二篇标题", "start_line": 10, "end_line": 17}
  ],
  "excluded_ranges": [
    {"start_line": 1, "end_line": 1, "reason": "合集总标题，不属于任一篇正文"}
  ]
}
```

行号从1开始，首尾都包含。CRLF/CR按换行计数；items按原文顺序，不得重叠。所有非空行都须在篇目或有理由的排除范围内。只排除已说明不使用的内容，不能以排除范围掩盖缺失的开场、细节或结尾。映射只能引用用户本次提供或明确授权的文件。

源内容变更需重新核对映射；已有 Run 不可用新内容冒充旧参考。只有所有逐篇分析完成，才能说“逐篇拆解完成”；全文保留、转换成功或文件已登记均不代表已经分析。
