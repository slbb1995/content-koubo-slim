# 三种模式共用的口播规则

## 守住任务

- 正文始终回答 `topic_original`，面向 `target_audience` 兑现 `approved_direction.core_promise`；
- `must_keep` 自然进入正文，`must_avoid` 不得出现；
- 事实不足时在原题内收窄，不改成“如何核验别人内容”等相邻安全题；
- `secondary_tactics` 只局部影响开头、节奏或收束，不成为第二主模式。

## 为耳朵写

- 像当面解释，不像报告、课程提纲或广告；
- 开头尽快进入具体问题、处境或判断，不用“今天聊聊”“随着发展”热身；
- 一句话只推进一个主要意思，长短句自然交替，代词指向清楚；
- 每段增加判断、方法、原因、处境、例子或后果，不换词重复；
- 专业区别确实影响判断时，紧接一句普通人能复述的话；不连续朗读术语和合同条件；
- 不写 Markdown 标题、表格、镜头提示、编辑说明、来源清单或内部流程词。

## 让内容具体

- 直接写对象、动作、条件和后果，不用抽象词代替内容；
- 避免 `看清楚、更稳、接住、有地方接` 等空泛表达；
- 避免 `认知升级、底层逻辑、赋能、闭环、抓手、颗粒度、链路、方法论、解决方案` 等企业术语；
- 不工整套用“不是 X 而是 Y”“你以为 X 其实 Y”等标准答案句式；
- 结构是写作工具，不是段落清单，不机械凑三点、反方、边界、故事或金句。

## 来源角色

- `selected_external_reference_mechanisms`：这是同版详细拆解报告形成的 Writer 详细蓝图。按逐篇内容价值、钩子、结构、可迁移项和冲突处理组织正文，并把禁止迁移项当作硬边界；不能只根据客户五组摘要自由发挥；
- `selected_04_content_assets`：提取通用问题、判断和内容价值，不能复制同行身份、经历、业务、案例、专属数据或识别性长句；
- `selected_04_method_assets`：只借表达顺序、钩子、节奏和结构方法；
- `selected_03_business_assets`：只在其局部片段支持范围内写客户专属业务；
- `profile_context`：只在已选逐字片段支持范围内写讲述者事实和关系；候选素材不自动变成真实经历；
- 缺少客户专属资料时，用一般性或条件性表达，不补造产品、数字、案例、群体趋势、服务或结果承诺。

## 故事与关系

- 当前 Profile 明确支持本人关系时，才写“我的客户”“我亲自处理过”；
- 关系未知时用“有位客户”“有这样一个情况”等中性说法；
- 纯解释场景用“比如”“假设”等自然标记；
- 普通生活情节不能证明产品效果、核保、理赔、真实业绩或群体结论。

## 动作与停止

- P4 没有明确动作授权时自然结束，不追加关注、评论、私信、领取、咨询、加好友、预约或购买；
- 不生成标题、发布正文、标签、拍摄提示或保存信息；
- 输出前通读一遍：能否直接说出口、是否仍在回答原题、是否有一句空话能删、是否越过来源边界。
